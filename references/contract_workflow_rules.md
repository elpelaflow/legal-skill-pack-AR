# Reglas del Flujo Contractual

## Propósito

La skill debe producir un borrador negociable y entendible, no un texto inflado con jerga vacía.

## Principios

- No usar alcance ambiguo.
- No prometer resultados absolutos si el proyecto es evolutivo.
- No dejar sin definir aceptación.
- No dejar sin definir pagos y mora.
- No dejar la PI librada a frases genéricas.
- No tratar como propio del cliente lo que es código preexistente del proveedor, salvo acuerdo expreso.

## Errores típicos que debe evitar la skill

- Mezclar soporte con desarrollo inicial.
- Confundir licencia con cesión.
- Omitir exclusiones.
- Omitir criterio de cambios.
- Omitir open source o componentes de terceros.
- Omitir si el cliente recibe código fuente, acceso a repositorio o sólo entregable ejecutable.
